# 解説文生成スキル

解説文（simple・summary・eliminationReasons）を生成するときの手順。

---

## 前提：ターゲットの解像度

「AI用語に躓いた非IT系の初学者」とは：
- 「RNN」「Transformer」など、生活に登場しない用語を見た瞬間に脳が閉じる
- 概念がわからないのではなく、用語の意味が回路に繋がらず処理できない
- 「わかるようでわからない言葉」でわかったつもりになり、素通りする
- 解説を読んで「わかった」と思っても、問題文に戻ると別世界に感じる

## ターゲットの成功体験

1問解くたびに「わからない用語が1つ減る」体験を作る。

- 最初は問題文を見ても何もわからない
- 解説を読んで「あ、あれか」とイメージが繋がる
- 同じ問題を繰り返すうちに「もう知ってる」になる

解説の目標は「理解させること」ではなく
「次にこの用語を見たとき、すでに知っているものとして脳が受け取れること」。

---

## 生成手順

### STEP 1：やさしい世界から入る
- 日常生活の具体的な体験から書き始める
- 例：「YouTubeが次の動画を予測できるのは…」
- 用語より先に体験を置く

### STEP 2：言葉を一つずつ検査する
以下の順で各言葉を確認する：

1. 生活の中で使う言葉か？
   → YES：そのまま使う
   → NO：次へ

2. 頭の中で動きが再生されるか？
   → 再生できる：OK
   → 再生できない：言い換える
   例：
   - 「最適化」→ 動かない → NG
   - 「何度も試して一番うまくいく形にする」→ 動く → OK
   - 「特徴の数値セット」→ 動かない → NG
   - 「特徴を数値化した組み合わせ」→ 動く → OK

3. 「わかるようでわからない言葉」になっていないか？
   → IT用語でも日常語でもない中間の言葉に注意
   → わかったつもりで素通りされる言葉は言い換える

### STEP 3：翻訳の瞬間を作る
やさしい世界の説明が終わったら、試験語への橋を2文で入れる。

- 1文目：「この仕組みを試験では『○○』と呼びます」
  → やさしい世界と試験語を繋ぐ
- 2文目：「○○は、〜です」
  → 試験語の定義を一言で添える

例：
「この仕組みを試験では『ボルツマンマシン』と呼びます。
ボルツマンマシンは、データの特徴や確率的なパターンを学習できます。」

これがないと、問題文に戻ったとき読者は別世界に放り込まれる。

### STEP 4：文量を確認する
- simpleは3〜5段落を目安にする
- 一段落に一つの概念だけを入れる
- 読んでいて息が詰まらないか確認する

---

## 禁止事項
- IT専門用語をそのまま使わない（どうしても必要なら日常語で言い換えを添える）
- 「〜という概念があります」「〜と定義されています」という説明調を使わない
- 責めるトーンにしない（「明らかに違います」などはNG）
- simpleの内容とsummaryが矛盾しないこと
