# 学習フロー設計スキル

このアプリの学習フローの設計思想と章別方針。

---

## 基本フロー

```
導入 → 問題文（読むだけ） → 解説 → 穴埋めチャレンジ → 問題回答 → 答え合わせ
```

**導入と解説は別物：**
- 導入：感情的な入口。「これ知ってる」「なんで？」という引っかかりを作る
- 解説：試験語彙への橋渡し。やさしい世界から試験語に繋ぐ

**解説と答え合わせ解説も別物：**
- 解説（simple）：概念を理解させる
- 答え合わせ解説（eliminationReasons）：「なぜ①が正解でほかが違うか」を扱う

---

## 章別方針

| 章 | 解説スタイル | 理由 |
|---|---|---|
| 第2章 | 重厚（仕組み系・比較系・歴史系・サービス系） | 生活に登場しない用語が多く、思考がフリーズするレベルの難しさ |
| 他章 | シンプル＋必要箇所に一行補足 | 「知らない」レベルであり重厚な解説は不要 |

---

## 問題タイプ別の解説スタイル

| タイプ | 解説スタイル | 穴埋め | 誤答排除 |
|---|---|---|---|
| 仕組み系 | 因果関係で説明 | B形式 | あり |
| 比較系 | 対比構造で説明 | B形式 | あり |
| 歴史系 | 時系列で説明 | B形式 | あり |
| サービス系 | 名前と用途の対応を説明 | B形式 | あり |
| 知識系 | 一行補足 | なし | なし（一部あり） |

---

## 新機能を追加するときの判断基準

1. 「脳が閉じる問題」を解決するか？それとも別の問題を解決するか？を明確にする
2. 既存フローのどこに入るかを確認する
3. 文量・認知負荷が増えないかを確認する
4. テストユーザーで検証してから本実装する
